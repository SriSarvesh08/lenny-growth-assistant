# System Design

## 1. User Interface (UI/UX)
* **Framework:** Next.js (App Router).
* **Styling:** Vanilla CSS or CSS Modules (Tailwind avoided unless strictly necessary) focusing on a clean, minimal, chat-centric interface.
* **Layout:**
  * **Left Sidebar:** Chat session history (allowing independent, persisted sessions).
  * **Main Chat Area:** Standard messaging interface.
  * **Right Panel (Artifact Viewer):** A secure, isolated panel that opens when the Agent generates a "Ship 30 for 30" essay or a Markdown/HTML document.

## 2. Artifact Viewer Security Design
The Artifact Viewer is a critical component requiring strict security to prevent Cross-Site Scripting (XSS).
* All HTML/Markdown generated by the LLM will be parsed and sanitized using `DOMPurify` before rendering in the React DOM.
* Alternatively, the artifact can be rendered inside a sandboxed `<iframe>` with `sandbox="allow-scripts"` explicitly disabled.

## 3. Dedicated Skills Design
The agent will be equipped with explicit tools:
* `search_lenny_knowledge(query: str)`: Executes a vector search against the `pgvector` database and returns transcript chunks.
* `write_ship30_essay(topic: str, context: str)`: Triggers a specific prompt template to format the provided context into the strict "Ship 30 for 30" structure (Catchy hook, 3 main points, concise conclusion).

## 4. Data Storage Model (PostgreSQL)
* **Sessions Table:** `id`, `created_at`, `title`
* **Messages Table:** `id`, `session_id`, `role`, `content`, `created_at`
* **Transcripts Table:** `id`, `episode_title`, `date`, `source_url`
* **Embeddings Table:** `id`, `transcript_id`, `chunk_index`, `content`, `embedding` (vector column)
